# v1.1 HTTP 接入约定

路径均相对于 `/api/v1`，机器可读字段见 [OpenAPI](openapi.json)。除 OAuth callback 外，下列接口要求 Owner 会话 Cookie。写操作还要求匹配服务端公开地址的 `Origin`、`X-CSRF-Token` 和非空 `Idempotency-Key`（最多 200 字符）。同一 Owner 的相同 key 绑定方法、路径和请求体；不同请求复用返回 409，相同已完成请求返回原结果。未确定状态返回 409。普通 JSON 请求体上限 65536 字节；附件上传上限 12 MiB，迁移扫描上限 24 MiB。响应通常为 `{data,requestId}` 或 `{error,requestId}`。

## 迁移

- `GET /migrations`、`GET /migrations/{id}` 和 `GET /migrations/compatibility` 查询批次和兼容范围。
- `POST /migrations` 必须提供 `system` 和 `instanceId`，并选择 `archiveBase64` 加 `sha256`，或 `directory` 加可选 `workspace`。归档解码上限 16 MiB；目录必须在已配置只读来源根目录下。
- `POST /migrations/{id}/plan` 接受可选 `choices`。策略为 `keep`、`new` 或 `manualmerge`；冲突采用合并策略时必须提供 `content`。apply 必须提供确切 `planHash`、Owner 密码和 `confirm:true`；rollback 同样要求密码与确认。
- `GET /migrations/history?search=...`、`GET /migrations/history/{id}` 查询历史；`POST /migrations/history/{id}/continue` 接受可选 `name` 和 0–50 的 `messageLimit`，创建新会话并附上不可信背景。
- `POST /migrations/objects/{id}/memory` 要求 `approved:true`、`scope`、`content`。`draft` 接受可选 `toolMap` 和 `requiredTools`。`review` 要求 `approved:true` 和适合 skill 或 cron 的 `mapping`，可带工具映射；审核结果默认禁用。`activate` 要求 `confirm:true`，并检查目标是否变更。

## Gmail 与附件

- `GET/POST /artifacts` 列出或创建受管附件；`GET /artifacts/{id}` 返回元数据。上传要求文件名、允许的 MIME 类型、base64 和 SHA-256；解码后单项最多 8 MiB，存储最多 256 项和 100 MiB。邮件附件只引用 `artifactId` 和 `filename`。
- `GET/POST /app-connections` 列出或创建连接。创建必须提供 Gmail provider、label、account、`accountConfirmed:true`、clientId 和精确白名单 redirectUri；clientSecret 可选。账号地址由 Owner 确认，Google 的 `gmail.send` scope 不核验该地址的身份。
- `POST /app-connections/{id}/oauth/start` 返回授权地址；`POST /app-connections/{id}/test` 检查连接；`DELETE /app-connections/{id}` 要求 Owner 密码与 `confirm:true`，并撤销连接。
- `GET /oauth/google/callback` 是例外：使用单用 state 和 PKCE，不依赖 Cookie，也不要求 Origin、CSRF 或幂等键。成功或用户取消时响应 303 到 `/`，包含 `Referrer-Policy: no-referrer`；失败返回 JSON。不要把它纳入普通 Cookie 保护矩阵。
- `GET/POST /action-intents` 列出或提出发送意图。Owner 可通过 `GET /action-intents/{id}/decision` 查看预览和确切 `inputHash`，再以 `POST` 提交 `APPROVED` 或 `REJECTED` 与该 hash。`send` 必须携带相同 hash；`cancel` 和 `dry-run` 使用空对象。符合明确规则的意图也可由后台发送。
- `GET/POST /app-rules`、`PATCH /app-rules/{id}` 管理绑定账号、profile、workflow、模板和内容哈希、收件人或域名、有效期与预算的规则。`GET/POST /app-grants`、`PATCH /app-grants/{id}` 管理账号与主体、profile、task、workflow 的授权。

`CONFIRMED` 表示 Gmail API 返回消息 ID，不表示收件人已收到。发送结果不确定时不自动重试。邮件正文默认在终态清理；`gmailBodyRetentionDays` 可设 0–365 天。连接凭据和正文不应进入普通日志。自动化测试使用 fake 上游，真实 Google 账号授权和发送尚未验收；见 [Gmail](GMAIL.md)。

`PATCH /settings` 当前还接受 `maxConcurrentRuns`（1–2）和 `maxQueueLength`（1–100）。完整字段见 OpenAPI。接口存在和 fake 测试通过均不代表真实服务验收。

## P0 审计后补充接口

以下接口均在 `/api/v1/` 下，要求已登录的 Owner。写接口沿用 Origin、CSRF 与幂等键检查。

| 方法与路径 | 行为 |
|---|---|
| `GET /memories/export` | 返回 `{version:1, exportedAt, items}`。包含本实例 Owner 可管理的记忆，不包含密码/模型/OAuth 秘密库或候选审核实体。导出仍是私人数据。 |
| `GET /settings/history` | 返回 `{items}`，元素为系统指令版本 `{version, content, at}`，按版本倒序。 |
| `GET /tasks?conversationId=<id>` | 仅返回该会话任务；可与 `status`、`source` 过滤组合。任务详情包含 `approvals`。 |
| `GET /heartbeats/{id}/history` | 返回关联任务历史。 |
| `POST /heartbeats/{id}/actions` | 接受 `{action:"run"|"pause"|"resume"}`。手动运行仍创建普通受预算/权限约束的任务。 |
| `GET /system/summary` | 增加应用 `version`、`piVersion`、通道状态和 `usageToday`。今日账本按 UTC 统计；`unknownCost:true` 时金额包含预留估价，不代表实际结算。 |

`GET /health/ready` 实际查询 SQLite，并检查 adapter、调度器启动、维护/磁盘/停机保护；失败为 503。`GET /health/live` 仅表示进程能够处理请求，不把外部供应商故障当作进程死亡。

IM 工具审批使用带到期时间的纯文本通知，正文不包含操作参数或秘密。通知本身不授予权限；Owner 必须登录管理台核对并批准确切操作。Telegram 生产控制面保留话题和引用标识；群组按发送者与话题隔离会话，出站重查发送者 allowlist。当前附件策略是仅接收文本，不下载平台附件。
