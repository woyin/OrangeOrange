## 交付状态

本轮实现 Telegram、WhatsApp Cloud API 和微信 iLink 的私聊文本适配、持久化接收与投递、分身份记忆/历史/提醒、记忆类型与来源、实时记忆检索、快照刷新、可维护提示词和 v1 数据迁移。

代码及本地自动化验证已通过。真实模型、真实平台账号、微信扫码资格和公网 WhatsApp 回调尚未联调。不能把协议替身通过解释为账号已经上线。

## 渠道证据

`tests/channel-adapters.test.ts` 验证：

- Telegram getUpdates 游标与私聊文本解析，忽略群聊和附件；纯文本发送、回执和错误分类。
- WhatsApp GET challenge、POST 原始正文 HMAC-SHA256 验签、篡改拒绝、接收失败返回 503，以及 Cloud API 发送形状、回执和 24 小时窗口。
- 微信 get_updates_buf、文本 item_list、context_token、稳定 client_id、扫码响应和 0600 凭据保存；拒绝非微信域名重定向。

`tests/gateway.test.ts` 的 8 项测试验证：

1. 接收去重、用户授权、独立会话与 /new 记忆快照。
2. 分段发送结果未知后停止自动重发；重启后人工重试仅处理未确认段，不重跑模型。
3. 来源渠道提醒队列去重，外部发送不自动改变已读状态。
4. 独立进程发送中 SIGKILL，恢复后为 unknown，不再次调用发送接口或模型。
5. 同一聊天的分段回复不与后续回复交错。
6. 接收成功后保存轮询游标，重启恢复游标并抑制重复输入。
7. 删除用户授权后不发送其已排队回复。
8. 明确限流最多尝试三次，然后进入人工处理状态。

测试使用协议替身及本地 loopback HTTP，没有向真实联系人发送消息。

## 记忆与提示词证据

`tests/scopes-migration.test.ts` 验证：

- 不同 scope 中相同记忆 ID 可以独立保存；模型 memory_list、历史搜索、提醒列表与取消均不跨身份。
- 相同内容/类型的新记忆返回已有记录；空闲会话可显式刷新；运行中在同一提交内拒绝刷新。
- 模型请求中包含身份渠道、记忆资料与证据规则。
- 使用实际 v1 SQLite，迁移旧 AppState、Profile 和尚未交付的提醒任务；原记忆、会话与提醒继续可用。

原有记忆、中文历史、工具循环、备份恢复、文件锁和崩溃恢复测试仍包含在本轮完整回归中。容量测试改用三条不同内容，因为本轮增加了重复内容合并。

文件工具另加入私有数据目录拒绝规则。测试工作区与私有数据目录改为分离布局，避免测试依赖读取私有目录的行为。

## 需要真实账号补齐的验收

配置方法见 [CHANNELS.md](CHANNELS.md)。所有配置由本机管理员提供；程序不会读取 Pi CLI 的凭据，也不会从其他项目寻找 token。

| 渠道 | 补齐条件 | 实际验收 |
|---|---|---|
| Telegram | bot token、允许的数字用户 ID、可访问 Bot API | 发私聊，收到回答；重启不重复回答；未授权用户不触发模型 |
| WhatsApp | Cloud API 业务号码、access token、应用密钥、版本、HTTPS 回调与订阅 | challenge 成功；签名回调进入队列；窗口内回复；窗口外保持明确失败 |
| 微信 | iLink 账号资格、扫码确认或有效 token、允许的 user ID | 私聊文本收发；重启后游标和 context_token 延续；过期状态可诊断 |
| 模型 | OPENAI_API_KEY | 执行 npm run smoke:live，确认实际工具调用及持久化结果 |

本轮没有创建公网域名、隧道、Meta 订阅或平台账号。真实账号验证前，不承诺平台限额、长期连接稳定性或 iLink 当前账号可用性。

## 明确边界

- 仅文本私聊；没有媒体、普通微信群、企业微信、公众号或个人 WhatsApp 扫码协议。
- WhatsApp 不实现模板消息，窗口外主动提醒可能无法发送。
- unknown 不保证恰好一次；人工重试仍可能重复已被平台接受的消息。
- 不同人的记忆默认独立；跨渠道共享需显式绑定 scope，且每个平台只能有一个允许用户。
- scope 隔离不提供操作系统隔离。所有获准用户共用管理员指定的只读工作区。
- 记忆仍是有界、人工可核查的资料；未实现向量检索或自动技能学习。
- 旧数据可以升级到 v2；不支持旧版程序降级打开升级后的目录。
